# Ontology-Constrained Neural Reasoning in Enterprise Agentic Systems: A Neurosymbolic Architecture for Domain-Grounded AI Agents (arXiv 2604.00555, v5 2026-06-04 / 본문 v3.0.1 May 2026, Luong Tuan — Golden Gate Univ./FAOS & Sanyal — Novartis)

## 한 줄 요약
기업 에이전트에 **Role·Domain·Interaction 3계층 온톨로지**를 구조화해 주입(input-side coupling)하면, 특히 LLM 사전학습 지식이 약한 영역(베트남 금융 규제, 기업 고유 KPI 기준치, 역할별 의사결정 패턴)에서 정확도가 크게 오른다(Inverse Parametric Knowledge Effect). 현재 기업 시스템은 입력만 제약하고 출력은 검증하지 않는 "비대칭 결합" 상태이며, 출력 검증(L4)·폐루프(L5)로 가야 한다고 제안한다. 근거는 FAOS 플랫폼(22개 산업, 650+ 에이전트)과 1,800회 실험.

## 문서가 제시하는 분류 체계 / 아키텍처
- **3계층 엔터프라이즈 온톨로지 O = ⟨R, D, I⟩**
  - Role Ontology (R) — 역할이 어떻게 생각·결정·소통하는가
    - δ 의사결정 패턴 (strategic, data-driven, risk-averse 등)
    - μ 중점 KPI (ARR, NPS, churn_rate 등)
    - σ 소통 스타일 (executive / technical / compliance)
    - ε 전문 영역
    - α 승인 권한 (이 역할이 허가할 수 있는 결정)
  - Domain Ontology (D) — 산업 개념·관계·지표
    - V Verticals — 계층형 산업 분류(fintech.payments.card_networks), 상위 개념 상속
    - E Entities — 정의가 있는 도메인 개념(ARR = MRR × 12)
    - M Metrics — 정상 범위·world-class 벤치마크 포함 지표
    - G Governance constraints — 산업별 적용 규제
  - Interaction Ontology (I) — 조직 워크플로우
    - H Handoff patterns — 역할 간 인계(트리거, 필수 산출물, 승인 여부)
    - A Approval chains — 순서대로 승인해야 하는 역할 체인(타임아웃 포함)
    - P Escalation paths — 권한 초과 시 우회 경로
  - Composability — 스키마는 산업 불변, 내용만 산업별 교체(22개 vertical)
- **신경-기호 결합(coupling) 위치 분류**
  - Input-side (구현됨) — LLM이 받는 정보를 제약: 컨텍스트 주입, 도구 발견 필터링, 거버넌스 임계값
  - Process-side (부분 구현) — 추론 과정 제약: autonomy gate(block-first 승인), quality judge, escalation
  - Output-side (제안) — 생성 결과를 온톨로지로 검증
- **결합 성숙도 모델 L0~L5**
  - L0 Ungrounded — 온톨로지 없이 LLM 단독
  - L1 Context-Injected — 온톨로지를 프롬프트 컨텍스트로 주입
  - L2 Discovery-Constrained — 온톨로지로 사용 가능한 도구/스킬 필터
  - L3 Process-Gated — 실행 중 승인 게이트·에스컬레이션 강제
  - L4 Output-Validated — 생성 후 출력 검증·제약
  - L5 Closed-Loop — 입력 제약+추론 유도+출력 검증+경험 기반 온톨로지 진화
  - FAOS는 L2–L3 수준
- **"비대칭 결합(asymmetric coupling)"** — 입력은 엄격히 통제하나 같은 정의로 출력은 검증 안 함 → 완벽한 컨텍스트를 받고도 위반 출력 가능
- **FAOS 시스템 구성 (7 bounded contexts, DDD + Anti-Corruption Layer)**
  - Ontology Engine — 3계층 해석·검증·주입
  - Skill Registry — 의미 기반 스킬 발견
  - Agent Orchestration — LangGraph StateGraph(병렬 분기, 품질 검증)
  - Outcome Tracker — 월별 파티션 불변 이벤트 저장소(provenance chain)
  - Tenant Manager — DB/캐시/이벤트/API/설정 5계층 격리
  - Context Engine — 우선순위 기반 조립 + 토큰 예산 관리
  - Governance — autonomy gate, 비용 추적, 승인 워크플로우
- **9-node 에이전트 실행 그래프**: Intent Classifier → Router → Decomposer → Plan Generator → Parallel Executor → Specialist Executor(여기서 온톨로지 주입) → Quality Judge(거버넌스 집행) → Response Aggregator → Escalation Handler
- **Ontology Resolution Pipeline**: 산업 온톨로지 로드 → 테넌트 overlay 병합 → 역할/도메인/상호작용 추출 → 직렬화 → 우선순위 절단(R > D > I, Tmax 기본 2000 토큰); T1 in-process(300s TTL) + T2 Redis 캐시
- **온톨로지 진화 루프(L5 제안)**: discovery → proposal → expert validation → provenance 포함 integration
- **지식 기반 접근법 비교(관련연구 분류)**: RAG / KG integration / ontology-enhanced prompting / constrained decoding

## 실험·결과 요약
- **설계**: 5개 규제 산업(FinTech BSA-AML, Insurance, Healthcare HIPAA/CMS, 베트남 Banking SBV, 베트남 Insurance MoF) × 10 과제(용어3·지표2·규제2·역할2·교차1) × 4조건 × 3반복 = 모델당 600회, 3모델(Claude Sonnet 4, Qwen 2.5 72B, Gemma 4 26B MoE) 총 1,800회. Judge는 Claude Sonnet 4(temp 0) 고정.
- **조건**: C1 Ungrounded(L0) / C2 RAG-only(온톨로지 문서에서 큐레이션한 8문단 ~2,000토큰) / C3 Ontology-coupled(L2, 구조화 3계층 ~2,800–3,200토큰) / C4 Ontology+Process(L3, C3 + quality judge).
- **지표**: TF 용어충실도, MA 지표정확도, RC 규제준수, RS 역할일관성.
- **주 결과(Claude, Friedman)**: MA χ²=20.71 p<.001 W=.460(C1 vs C3 p<.001), RS χ²=27.64 p<.001 W=.614(p=.003), RC p=.003 W=.318(사후검정 비유의), TF p=.024 W=.157(사후검정 비유의).
- **평균 점수(Claude)**: MA C1 .37 → C3 .74, RS C1 ~.70 → C3 .92 수준; 그랜드 평균 C1 .58 / C2 .83 / C3 .77 / C4 .80.
- **산업별 Δ(C1→C3)**: FinTech +.12, Insurance +.08, Healthcare +.17, Banking VN +.29, Insurance VN +.28 → 베트남 영역이 영어 평균(+.12)의 약 2배.
- **Inverse PKE**: 잘 알려진 개념에서는 주입이 오히려 손해(FT-T7 PCI-DSS RC 1.00→.42, IN-T1 combined ratio .81→.50, IN-T2 persistency .87→.57). 가장 큰 개선은 기업 고유 지표·인계 SLA·역할 패턴(FT-T10 +.66, IN-T5 +.62).
- **RAG vs Ontology**: C2가 TF에서 C3보다 높음(.812 vs .711), C2–C3 차이는 어떤 지표도 비유의(p>.20). 단 Gemma에서 RS만 C3>C2 유의(p=.006). 온톨로지 형식의 토큰 오버헤드 40–60%.
- **C3 vs C4**: 차이 없음 — judge가 점수만 매기고 응답을 바꾸지 않았기 때문.
- **교차모델**: MA·RS는 3모델 모두 유의. 온톨로지 lift Claude +.15 / Qwen +.22 / Gemma +.20, Qwen > Claude 유의(p=.040) → 모델 수준에서도 Inverse PKE. RC는 모델 민감.
- **엔트로피**: 12개 지표×모델 중 11개에서 엔트로피 감소, 예외는 Claude MA(+0.04 bits).
- **판정자 불확실성 민감도**: 35% 불일치 가정 시 MA 효과 +.37 → 약 +.24로 축소되나 여전히 큼.

- **EDM Council — FIBO**, TOVE, BFO, DOLCE — 기존 엔터프라이즈/상위 온톨로지. 데이터 통합·상호운용 목적이지 에이전트 행동 제약용이 아니라고 평가.
- **Anthropic Claude Sonnet 4** — 주 생성 모델 + 판정 모델. 파라메트릭 지식이 강해 lift가 가장 작음(+.15), MA에서 엔트로피 증가(파괴적 간섭).

- **Google Gemma 4 26B (Google AI Studio 경유)** — lift +.20, RS에서 유일하게 C3>C2 유의.
- 대안 프레임워크로 **CrewAI, AutoGen, standalone LangGraph** 재현이 향후 과제로 언급.
- 관련 연구로 Governance-as-a-Service(Gaurav et al.), OntoTune(SNOMED CT), OG-RAG, GCR, SLOT 언급.

## 한계·미해결 과제
- 출력 검증(L4)·폐루프(L5)·온톨로지 진화는 설계만, 미구현·미평가.
- 온톨로지 완전성: 빠진 개념은 grounding 불가, 유지비용이 규제 변화 속도에 비례.
- OWL 검증의 실용성: 자유 텍스트 출력을 OWL 표현으로 변환하는 것 자체가 오류원.
- 단일 플랫폼(FAOS) 분석, 다른 프레임워크 재현 없음.
- LLM-as-judge 의존(전문가 κ 미검증; SME–LLM 일치 64–68% 문헌 인용), RS 개선에 judge 천장효과 가능성.
- RAG 베이스라인이 같은 blueprint로 큐레이션돼 비현실적으로 좋음 — 실제 이질적 문서 RAG라면 온톨로지 우위가 더 클 것으로 추정.
- 컨텍스트 간섭(주입이 파라메트릭 지식을 밀어냄): 적응형 주입 필요. 형식 효과 vs 분량 효과를 분리하는 토큰 예산 통제 실험 미실시. 계층별(R/D/I) ablation 미실시.
- 멀티테넌트 "ontological polymorphism"(같은 스키마, 테넌트별 다른 인스턴스) 과제.

## 기술 맵 관점 메모
- **"결합 위치" 축(input / process / output)** 과 **성숙도 L0–L5** 는 컨텍스트 엔지니어링 기술을 "주입 전·실행 중·생성 후"로 배치하는 좋은 세로축 — Context Kubernetes(2604.11623)의 거버넌스 계층은 주로 input+process 쪽에 해당.
- **지식 표현 형식 축**: 비구조 청크(RAG) → KG → 온톨로지(타입·제약·워크플로우 포함). 이 논문 결과상 어휘 회상은 RAG와 비슷하고, 차별점은 관계 추론(역할), 검증 가능성, 재사용성.
- **"주입량 최적화/선택적 주입"** 은 독립 노드로 둘 가치: Inverse PKE + context length 성능저하(Du et al. 13.9–85%) → "많이 넣을수록 좋다"가 아님. Self-RAG·적응형 주입·엔트로피 진단과 묶기.
- **역할(Role) 컨텍스트**는 사실 지식과 별개 범주로 맵에 표시 — 언어·모델 불문 가장 일관된 개선(RS)을 보임.
- **도구 발견도 컨텍스트 선별의 한 형태**(어떤 도구를 에이전트에게 보여줄지) → 수집/검색 단계와 실행·도구 단계를 잇는 노드.
- 기업 솔루션 맵에서는 Palantir Ontology(객체·링크·액션)와 대응시키기 좋은 학술 근거이지만, 논문 자체엔 비교가 없으므로 맵에서 "개념적 유사(직접 근거 없음)"로 표기할 것.
